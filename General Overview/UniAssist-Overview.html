UniAssist — Project Overview

Project: UniAssist

Team: Balerioncodes

Document Version: 1.0

Year: 2026

What We Are Building

UniAssist is a student support platform. The goal is simple: give students one place to get help with anything academic, technical, or project-related — without the confusion of chasing people across WhatsApp, email, or social media.

A student logs in, describes what they need, uploads any relevant files, and submits a request. The UniAssist team reviews it, sends a quote, the student pays, and work begins. The student can track everything — status, messages, files, and deliverables — from a single dashboard.

It is not a tutoring marketplace. It is not a freelancing platform. It is a managed support service where the UniAssist team handles everything directly.

The Problem We Are Solving

Students regularly need support that falls outside what their institution provides:

  • A deadline is approaching and they are stuck on a programming assignment
  • They need help structuring a research paper
  • Their development environment is broken and they do not know why
  • They are building a final-year project and have no one to guide them
  • They need past questions or study materials in one place

The current alternatives are unreliable — asking friends, searching forums, hiring random freelancers with no accountability, or simply giving up. There is no structured, trustworthy, student-focused service that handles all of this in one place.

UniAssist fills that gap.

Who It Is For

Students

The primary users. Students submit requests, communicate with the team, make payments, and receive support. The platform should feel effortless for them — clean, fast, and reassuring.

The UniAssist Team

The internal team manages every request from submission to completion. They review requests, assign work, create quotes, communicate with students, upload deliverables, and track everything through the admin dashboard.

Visitors

People who land on the platform without an account. The public website explains what UniAssist does and converts them into registered students.

What the Platform Will Do

For Students

  • Create a detailed support request in a step-by-step guided form
  • Upload files, specify deadlines, and describe the problem clearly
  • Receive a quote from the team and accept or decline it
  • Pay securely through the platform
  • Track request progress through a full status timeline
  • Communicate directly with the assigned team member
  • Receive and download completed deliverables
  • Browse a resource library of study materials, guides, and past questions
  • Get notifications for every update without having to check manually

For the UniAssist Team

  • View and manage every request from a central admin dashboard
  • Search, filter, and sort requests by status, category, urgency, and deadline
  • Assign requests to team members
  • Create and send quotes to students
  • Update request status at each stage
  • Communicate with students through per-request messaging
  • Upload deliverables when work is complete
  • Monitor revenue, payments, and team workload
  • Manage the resource library
  • View platform analytics

How It Works — End to End

Student registers and verifies their email
        ↓
Student submits a request (category, description, deadline, files)
        ↓
Request enters the queue as SUBMITTED
        ↓
Admin reviews the request → status: UNDER REVIEW
        ↓
Admin creates a quote (price, timeline, scope)
        ↓
Student receives notification → reviews and accepts the quote
        ↓
Student makes payment through Paystack
        ↓
Payment confirmed by webhook → status: PAID
        ↓
Admin assigns request to a team member → status: ASSIGNED
        ↓
Work begins → status: IN PROGRESS
        ↓
Team submits for internal review → status: REVIEW
        ↓
Admin marks complete, uploads deliverables → status: COMPLETED
        ↓
Student downloads deliverables, request closes → CLOSED

Throughout this entire flow, the student and team can message each other inside the platform. Every status change is logged and visible on the request timeline.

What the Finished Product Looks Like

Public Website

A clean, professional landing page that communicates the product clearly. Sections for services, how it works, testimonials, and a strong call to action. No clutter. No generic template styling. It should feel like a modern SaaS company, not a university portal.

Student Application

A focused dashboard where students can see all their active requests at a glance, create new ones, track progress, chat with the team, and manage payments. Every screen is responsive and works properly on mobile.

Admin Application

A powerful but clean internal dashboard. The team can manage the full request queue, monitor workload, handle payments, and communicate with students — all without needing any external tools.

The Technology Foundation

The platform is built to be maintainable, scalable, and cost-effective for a small team.

LayerChoiceReason
FrontendReact + TypeScript + ViteFast, modern, strongly typed
StylingTailwind CSS + shadcn/uiConsistent design with minimal overhead
BackendSupabaseManaged Postgres, auth, storage, realtime, and serverless functions in one platform
PaymentsPaystackReliable payment processing for the target market
DeploymentVercel + Supabase CloudSimple, scalable, low-maintenance hosting

There is no custom API server to maintain. Business logic that requires elevated privileges or third-party service calls runs through Supabase Edge Functions. Security is enforced at the database level through Row Level Security policies.

Development Phases

Phase 1 — Frontend Design (Current)

Three developers independently build the full frontend using shared specifications. This produces three different visual interpretations of the same product. The strongest design is selected by team vote.

Phase 2 — Frontend Selection

The team reviews all three implementations and votes. The selected frontend becomes the official codebase going forward.

Phase 3 — Backend Development

The full team builds the Supabase backend together — database schema, RLS policies, Edge Functions, storage, and Realtime. This phase connects the real data layer to the winning frontend.

Phase 4 — Integration

The selected frontend is connected to the production backend. Mock data is replaced with real Supabase queries. All services (auth, payments, messaging, notifications, file storage) are wired up and tested end to end.

Phase 5 — Launch

The platform is deployed to production. Real students can register and submit requests. The team begins fulfilling requests through the admin dashboard.

Quality Standards

The platform must meet these standards before launch:

  • Responsive — fully functional on desktop, tablet, and mobile
  • Fast — pages load quickly, dashboards do not lag
  • Secure — no data leaks across users, payment confirmation only via server-side webhook
  • Reliable — requests, payments, and messages do not fail silently
  • Accessible — readable contrast, keyboard navigability, clear error states
  • Maintainable — clean code structure that any team member can work in without a lengthy onboarding

What Success Looks Like

At the end of development, we have a platform where:

  • A student can sign up, submit a request, pay, and receive completed work entirely within UniAssist — without a single external message or file exchange
  • The team can manage their full workload from the admin dashboard without needing spreadsheets, WhatsApp threads, or manual tracking
  • The codebase is clean enough that new features can be added without breaking what already works
  • The platform is live, stable, and actively serving real students

That is the goal. Everything in the technical documentation exists to support it.
